## 1. プロジェクト概要

### 1.1 プロジェクト名
DBD Subtitle Translator（仮称。正式名称は開発中に決定）

### 1.2 目的
外国語で収録された Dead by Daylight（DBD）のゲームプレイ動画を入力し、動画内の音声を
自動認識・文字起こし・日本語翻訳し、動画編集に利用可能な日本語字幕データを生成する
デスクトップツールを開発する。

本ツールは韓国語専用ではなく、英語圏・韓国語圏・EU 圏など多言語の DBD コンテンツを対象とする。

最終的な目標は単純な機械翻訳ではない。外国人 DBD プレイヤー同士の会話を、ゲーム内の文脈・
DBD 用語・各言語圏のゲームスラングを理解したうえで、日本の DBD プレイヤーが自然に理解できる
日本語へローカライズする。

## 3. 開発方針

### MVP
「DBD 動画向け音声認識・翻訳パイプライン」を完成させる。ゲーム音と VC の完全分離や
複数話者の完全な個別認識は必須としない。

```
動画 → 音声抽出 → 多言語音声認識 → 原文字幕 → 文脈を考慮した日本語翻訳 → 字幕生成 → SRT 等
```

## 5. 対象ユーザー
海外 DBD プレイヤーの動画を日本語化して YouTube 等で公開する動画制作者。

主な用途: 海外 DBD プレイヤーの動画翻訳 / 海外大会・競技シーンの翻訳 / 海外プレイヤーの VC 翻訳 /
DBD 解説・実況動画の翻訳 / 外国語動画から日本語字幕を作成する作業の効率化

## 6. 対応言語

### 6.1 入力言語
特定言語に依存しない多言語設計とする。優先対象:
英語 / 韓国語 / ドイツ語 / フランス語 / スペイン語 / イタリア語 / ポルトガル語 /
ポーランド語 / オランダ語 / その他、採用 ASR が対応する言語。

**英語圏・韓国語圏・EU 圏のいずれかに固定しない。**

### 6.2 言語判定
原則として自動判定。ただしユーザーが手動指定できるようにする（Auto Detect / English / Korean / …）。

### 6.3 出力言語
MVP では日本語のみ。ただし翻訳レイヤーは将来的な多言語出力に対応できる構造とする。

## 7. MVP 基本ワークフロー

```
元動画 → メディア解析 → 音声抽出 → 音声前処理 → 多言語 ASR
     → 外国語文字起こし → タイムスタンプ付き原文セグメント
     → 文脈整理 → LLM による日本語翻訳 → 字幕品質最適化
     → 原文＋日本語字幕 → SRT / ASS 等
```

---

## 8. MVP 成功条件

1. 外国語 DBD 動画を読み込める
2. 動画から音声を抽出できる
3. 多言語音声認識ができる
4. タイムスタンプ付き原文テキストを生成できる
5. 原文を保持したまま日本語へ翻訳できる
6. 前後の発言を考慮した文脈翻訳ができる
7. DBD 用語を考慮できる拡張構造を持つ
8. 字幕として読みやすい形へ整形できる
9. SRT 等の字幕ファイルとして出力できる
10. 作業状態を保存し、後から再開できる

MVP の目標は「完全自動で 100 点の字幕」ではない。
**AI が生成した字幕を人間が確認・修正することで、実用的な動画字幕として完成させられる状態**をゴールとする。

## 9. ASR（音声認識）要件

### 9.1 ASR は事前評価で選定する
WhisperX 等を最初から採用決定しない。複数の多言語 ASR を比較し、DBD 動画に対する実用性を
評価したうえで MVP に採用する ASR を決定する。

### 9.2 評価項目
英語 / 韓国語 / ドイツ語 / フランス語 / スペイン語 / その他主要言語の認識精度、
ゲーム実況音声への対応、VC 音声への対応、ゲーム音が混ざった音声への対応、ノイズ環境への対応、
タイムスタンプ精度、長時間動画への対応、ローカル実行可能性、GPU 利用効率、処理速度、
VRAM 使用量、API コスト、ライセンス、話者分離との将来的な統合性

### 9.3 ベンチマーク
実装開始前に、実際の DBD 動画を利用した評価方法を提案する。評価対象は英語 / 韓国語 / EU 圏言語の
DBD 動画、ゲーム音が強い動画、VC が明瞭な動画、複数人 VC 動画などとする。

### 9.4 ASR Provider 設計
ASR エンジンはアプリケーション本体から分離する。将来的に交換可能にする。

```
ASRProvider
├── Provider A
├── Provider B
├── Provider C
└── Future Provider
```

## 10. MVP 音声処理
ゲーム音と VC の完全分離は必須としない。`動画 → 音声抽出 → 音声前処理 → ASR`。
ただし将来の音源分離を考慮し、音声処理部分を独立モジュールとして実装する。

## 11. 将来の音源分離
`Mixed Audio → Source Separation → { Game Audio, Voice Audio }`。
ゲーム音を除去するだけでなく、ゲーム音自体を将来的なゲーム状況解析へ利用できる構造を検討する。

## 12. 将来の話者分離
Speaker Diarization を導入する。話者数は 4 人固定ではなく可変。

```
Speaker
├── speaker_id
├── label
├── start_time
├── end_time
└── confidence
```

## 13. 将来の複数人音声認識
プレイヤーごとの個別認識を可能にする。同時発話・重複発話も将来的な対応対象とする
（完全な音源分離・完全な重複発話認識を保証するものではない）。

---

## 14. 翻訳エンジン
MVP では LLM を利用した外国語 → 日本語翻訳を基本とする。Provider 方式で抽象化し、
特定の LLM へロックインしない。

```
TranslationProvider
├── Claude
├── GPT
├── Gemini
└── Future Provider
```

## 15. 翻訳コンテキスト
各字幕セグメントを完全に独立して翻訳しない。必要に応じて以下を翻訳 AI へ渡す。

前の発言 / 現在の発言 / 次の発言 / 話者情報 / 原文 / DBD 用語辞書 / プレイヤー情報 / 翻訳履歴

## 16. DBD 用語辞書
設計段階から用意する。登録対象: キラー名 / サバイバー名 / パーク名 / アドオン / オファリング /
マップ名 / ゲーム内用語 / DBD コミュニティ用語 / スラング / プレイヤー名 / 固有名詞。

多言語の原語と日本語の正式名称・推奨訳を関連付けられる構造とする。

## 17. 将来の DBD スラング翻訳
単純な辞書置換ではなく、
`外国語 → 言語固有表現解析 → DBD コミュニティ上の意味 → ゲーム文脈 → 日本 DBD コミュニティで自然な表現`
というローカライズ処理を目指す。

## 18. 字幕データモデル

```
SubtitleSegment
├── id
├── start_time
├── end_time
├── original_text
├── translated_text
├── source_language
├── target_language
├── speaker_id
├── confidence
└── metadata
```

将来拡張用: `translation_provider` / `asr_provider` / `glossary_matches` / `review_status` /
`game_context` / `visual_context`

## 19. 字幕品質最適化
翻訳結果をそのまま字幕化せず、字幕として読みやすい状態へ自動調整する。

対象: 1 行あたりの文字数 / 最大行数 / CPS / 最小表示時間 / 最大表示時間 / 字幕間隔 /
文節 / 改行位置 / 不自然な分割 / 長すぎる字幕 / 短すぎる字幕

**この処理は翻訳 AI とは別の字幕処理層として実装する。**

## 20. 原文保持
原文は必ず保持する。ユーザーは原文と日本語訳を比較できるようにする。

```
00:01:12.300 → 00:01:14.800
Original:  여기 킬러 있어!
Japanese:  ここにキラーいる！
```

## 21. 信頼度・レビュー
可能な場合 ASR 結果等の confidence を保持する。低信頼度の字幕を将来的に自動でレビュー対象として
マークできるようにする。

## 22. 字幕編集機能（MVP 最低限）
日本語字幕編集 / 原文確認 / 開始時間変更 / 終了時間変更 / 字幕削除 / 字幕分割 / 字幕結合 /
話者変更 / 再翻訳 / 原文から再翻訳 / 保存

## 23. 動画プレビュー
字幕確認に必要な動画プレビューを実装する。Premiere Pro 等のような本格的な動画編集タイムラインは
MVP 対象外。

## 24. 出力
MVP: SRT。将来: ASS / VTT / 字幕焼き込み済み MP4。

## 25. プロジェクト保存
元動画への参照 / ASR 結果 / 原文字幕 / 日本語字幕 / タイムスタンプ / 話者情報 / 辞書情報 /
翻訳設定 / ASR 設定 / 編集履歴 / レビュー状態。

**アプリ終了後も作業を再開できることを必須とする。**

## 26. API キー・認証情報
LLM API キー等の機密情報をプロジェクトファイルへ平文保存しない。OS の安全な認証情報ストレージ等を
利用する。

## 27. ローカル処理とクラウド処理

```
ローカル: FFmpeg / 音声抽出 / 音声前処理 / ASR / 字幕処理 / プロジェクト保存

```

ただし ASR 選定時にローカル方式と API 方式を比較する。

## 31. 非機能要件

- **拡張性**: ASR、翻訳 AI、音声分離エンジンを交換可能なアーキテクチャとする
- **保守性**: 音声処理、ASR、翻訳、字幕処理、UI を可能な限り分離する
- **再現性**: 使用モデル・設定・翻訳プロバイダー等をプロジェクトへ記録する
- **中断耐性**: 長時間動画処理中にアプリが終了しても途中状態から再開できる
- **オフライン耐性**: API を必要としない処理は可能な限りローカルで完結させる

## 36. 最終的なプロダクトコンセプト

このツールは単なる「外国語を日本語に翻訳する字幕生成アプリ」ではない。

最終的には、**外国語で話される DBD プレイヤー同士の会話を理解し、日本の DBD プレイヤーにとって
自然な日本語として再構成するローカライズツール**を目指す。

そのため、多言語 ASR × 話者分離 × 会話コンテキスト × DBD 知識 × DBD スラング ×
ゲーム映像理解 × 字幕品質最適化 を段階的に統合する。

MVP ではその最初の基盤として、
**「多言語 DBD 動画 → 音声認識 → 外国語原文 → 文脈付き日本語翻訳 → 実用的な日本語字幕」**
というパイプラインを確実に完成させる。
